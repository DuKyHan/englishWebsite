# GS Unit Engine — reusable across Unit 1, 2, 3... 10

This is the refactored, modular version of the Unit-1 learning system.
The **engine never changes per unit** — only `data/unitN.json` does.

```
engine/
├── build.py                  ← CLI: python build.py data/unit1.json output/Unit1
├── schema/UNIT_SCHEMA.md      ← the data format every unitN.json must follow
├── engine/
│   ├── schema.py               validates a unitN.json before building
│   ├── common_js.py            shared JS (TTS, normalize, confetti...) — used by all 4 apps
│   ├── generic_lessons.py      Word-Formation guide + 6-step sentence-writing method
│   │                           (true for English in general, not unit-specific)
│   ├── build_vocab.py          → GS_UNITn_VOCAB.html
│   ├── build_grammar.py        → GS_UNITn_GRAMMAR.html
│   ├── build_inclass.py        → GS_UNITn_INCLASS.html
│   └── build_test.py           → GS_UNITn_TEST.html (auto-partitions ALL content, 0 hand-picking)
├── data/
│   └── unit1.json              Unit 1 (Leisure Time) content, already authored
└── output/
    └── Unit1/                  the 4 generated HTML files
```

## Building Unit 1 (already done)

```bash
python build.py data/unit1.json output/Unit1
```

This prints a content summary, runs the schema validator (fails loudly if
anything is missing or inconsistent — e.g. an MCQ answer index out of
range, a Word Formation item pointing at a word family that doesn't
exist), and writes the 4 self-contained HTML files.

## Adding Unit 2 (or any future unit)

1. Copy `data/unit1.json` to `data/unit2.json` as a starting template.
2. Replace every field with Unit 2's real textbook content, following
   `schema/UNIT_SCHEMA.md`. You do **not** need to:
   - write the Word-Formation "how to solve" guide (engine-level, generic)
   - write the 6-step sentence-writing method (engine-level, generic)
   - hand-pick which MCQ items go in the Grammar app's test (tag items
     `"grammar"` / `"vocab"` / `"mixed"` in the `mcq` list instead)
   - decide how many Test stages there are or which items go in which
     stage (the engine auto-chunks every category into ~10-question
     stages, in a fixed pedagogical order)
   - hand-generate Word-Form quiz distractors (the engine pulls 3
     distractors from the same `word_families` entry automatically, via
     each `word_formation` item's `family_base` link)
3. `python build.py data/unit2.json output/Unit2`
4. If the schema validator reports problems, fix `unit2.json` and rerun —
   it won't let you ship a unit with a missing answer, an out-of-range
   MCQ index, a Word Formation item that points at a nonexistent family,
   etc.

## What changed vs. the original 4 hand-built Unit-1 files

- **Before**: each of the 4 HTML files had its own copy-pasted TTS code,
  normalize() function, confetti animation, etc. — any improvement (like
  the better voice-picking logic) had to be manually copied into 4 places.
  **Now**: those live once in `engine/common_js.py` and are shared.
- **Before**: the Test app's 6 stages were built from hand-picked MCQ
  index lists (`vocab_idx = [9,10,11,...]`) — fragile, and impossible to
  redo for a new unit without re-picking indices by hand.
  **Now**: `build_test.py` walks every content category generically and
  auto-partitions it into ~10-question stages. Every future unit gets
  this for free.
- **Before**: the Grammar app's "Test tổng hợp" MCQ subset was also a
  hand-picked index list.
  **Now**: driven by `tags` on each `mcq` item (`"grammar"`/`"vocab"`/
  `"mixed"`), which is just normal content authoring, not index-picking.
- **Before**: the Word-Form quiz game's 4-option distractors were
  generated by a one-off script tied to Unit 1's specific word families.
  **Now**: `build_vocab.py::derive_wf_quiz()` does this generically from
  any unit's `word_families` + `word_formation.family_base` links.
- **Before**: no validation step — a typo'd answer index or a missing
  explanation would only surface as a visible bug in the browser.
  **Now**: `engine/schema.py` checks every category before any HTML is
  written, and `build.py` refuses to build until problems are fixed.

## Update: memory tips + "apply it now" mini-quizzes in the review tab (INCLASS)

Each topic in the **📌 Tổng hợp kiến thức** tab now has a `🧠 Mẹo ghi nhớ`
callout box and a small instant-feedback mini-quiz right under it, so
review is active practice, not just reading:

- **Phát âm -s/-es** and **Phát âm -ed**: mnemonic tip + 4 new generic
  practice items each — added to `generic_lessons.py`
  (`s_es_pronunciation_quiz()`, `ed_pronunciation_quiz()`), so every
  future unit gets these for free, same as the rule tables themselves.
- **Trọng âm**: mnemonic tip ("danh từ/tính từ nhấn âm 1, động từ nhấn
  âm 2, có ngoại lệ") + 4 new generic items — `stress_tip_html()` and
  `stress_basic_quiz()`, also engine-level.
- **Ngữ pháp**: reuses the first 4 items of the unit's own
  `comprehension_quiz` — no new authoring, just resurfaced for spaced
  repetition.
- **Word Formation**: reuses `build_vocab.derive_wf_quiz()` (the same
  function that powers the VOCAB app's WF game) on the unit's own
  `word_formation` + `word_families` data, taking the first 4 — again no
  new authoring needed, just cross-module reuse.

Each mini-quiz is click-once-then-locked with immediate ✅/❌ feedback and
a running score, independent of the main progress bar (this tab still
doesn't count toward the 12-part completion tracker).

## Update: per-option Vietnamese translations + a final "Kiến thức cần nhớ" review tab (INCLASS)

- Every MCQ item in `data/unit1.json`'s `mcq` list now carries a `vis`
  array (one Vietnamese gloss per option, explaining both why the correct
  option is right and why each distractor is wrong/different in form).
  No engine change was needed for this — `build_inclass.py`'s option
  renderer already supported an optional per-option `vis` field (it's how
  the Pronunciation/Reading sections show meanings); this was purely a
  content-authoring pass across all 30 items. `vis` is optional in the
  schema, so units that don't author it just won't show per-option
  glosses for that category.
- `build_inclass.py` now appends one more tab after the last exercise:
  **📌 Tổng hợp kiến thức**. It's a pure review page (no grading, doesn't
  count toward the progress bar) built from:
  - `generic_lessons.pronunciation_endings_guide_html()` — the -s/-es
    and -ed pronunciation rules (3 sounds each), new in
    `generic_lessons.py` and therefore free for every future unit;
  - an auto-generated **answer-key reference table** for the unit's own
    Pronunciation and Stress items (`_pron_stress_reference_html()`) —
    this is the "give the exercise examples back to students" part;
    fully generic, works for whatever pronunciation focus any unit has;
  - the unit's grammar lesson (reused, same content as the Lý thuyết tab);
  - the Word-Formation guide (reused, generic);
  - the vocabulary quick-reference table (reused).

## Update: audio + more Word Form practice modes (VOCAB app)

`build_vocab.py` now derives a `wfPool` (every form of every word family,
flattened) at build time from the same `word_families` data already in
the schema — no new fields needed in `unitN.json`. This powers 3 new
practice modes alongside the original Điền từ (fill) and Trắc nghiệm
(MCQ game):

- **🎧 Nghe & Chọn (Listen & Choose)** — TTS plays a word from the pool,
  student picks the correct spelling from 4 options.
- **🔗 Ghép cặp (Matching)** — click-to-pair a family's English forms
  with their Vietnamese meanings; "Nghe tất cả" plays every word in the
  group in sequence; "Nhóm khác" jumps to a different family.
- **🔤 Đánh vần (Spelling Challenge)** — hear the word + see its
  Vietnamese meaning and part of speech, type the correct spelling.

Speaker (🔊) buttons were also added throughout the Word Family & Word
Form tab that didn't have them before: every form in the family reference
cards, the root-word hint on each fill-mode item (plus the correct answer
once graded), and every option in the MCQ game. All audio goes through
the same shared `tts_js()` voice-picking logic in `common_js.py`, so any
future voice-quality improvement there applies to every mode at once.

## Regression-tested

The regenerated Unit 1 output (`output/Unit1/`) was run through the same
Playwright headless-browser test suite used for the original hand-built
files: all 4 apps load with zero console errors, every grading path
(MCQ, fill, sentence transformation) scores correctly, the Test app's
built-in content-audit banner reports 0 problems (107/107 items, no
duplicates, no missing answers/explanations), and completing every stage
awards the "Unit Complete" badge. Nothing regressed from the hand-built
version — some parts even improved (e.g. Test now auto-splits the 30-item
MCQ pool into three 10-question stages instead of one 30-question stage).
